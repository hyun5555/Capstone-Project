# 법률·전세계약 RAG 챗봇 설계

## 책임 분리

```text
사용자 질문
  → 개인정보 패턴 마스킹
  → legal_chunks 검색 (text-embedding-3-small)
  → LangChain 프롬프트 + gpt-5.6-luna
  → 답변 + 공식 출처
  → 실패 시 PostgreSQL keywords 35개 답변
```

챗봇은 법률 용어와 확인 절차만 설명한다. 매물의 위험 점수와 등급은 기존 서버 규칙이 계산하며 LLM은 이를 새로 계산하거나 변경하지 않는다.

## 저장 구조

`legal_data/legal_sources.json`에는 공식 출처의 제목, 기관, URL, 시행·확인일, 요약문을 둔다. 최초 질문 때 문서를 청킹하고 OpenAI 임베딩을 생성해 ChromaDB의 `legal_chunks` 컬렉션에 저장한다. 자료 파일 해시와 내용으로 ID를 만들기 때문에 같은 자료를 다시 색인해도 중복되지 않는다. 매물 문서용 `property_chunks`와는 컬렉션을 분리한다.

## 답변 안전장치

프롬프트는 검색된 공식 자료 밖의 추측, 위험도 산정, 개인 사건에 대한 단정적 법률 자문을 금지한다. 답변에는 `[1]` 형식의 근거 번호와 출처 URL을 표시하고 고정 면책 문구를 붙인다. OpenAI·임베딩·Chroma 검색이 실패하면 기존 키워드 DB로 자동 대체하며 내부 오류 내용과 API 키는 사용자에게 노출하지 않는다.

## 자료 갱신

법령이나 공공기관 안내가 바뀌면 `legal_sources.json`의 내용과 `effective_date`를 갱신한다. 파일 해시가 달라져 새 청크가 자동 색인된다. 현재 자료는 2026-09-21에 확인한 국가법령정보센터, 국토교통부, HUG 자료다.

## 검증 기준

1. 같은 자료를 여러 번 색인해도 현재 버전 청크 수가 늘지 않는다.
2. 답변에는 검색 근거와 공식 URL이 포함된다.
3. OpenAI 또는 Chroma 장애 시 기존 키워드 답변이 반환된다.
4. LLM 답변은 위험 점수 계산 결과에 영향을 주지 않는다.
