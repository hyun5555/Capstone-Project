# 법률·전세계약 RAG 챗봇 설계와 실측

## 처리 흐름

```text
Flutter 질문 + 계약 단계(계약 전/중/후)
  → 개인정보 마스킹 + 범위 밖 질문 차단
  → 공식 자료 12건 ChromaDB 검색
     └ 필요한 질문만 원문+법률용어 보강 질의를 한 번에 임베딩 → 가중 RRF → Top-3
  → ChatPromptTemplate(system + stage/question/context) → gpt-5.6-luna
  → [번호] 인용 검증 → 실제 인용한 출처만 반환
  → 인용 없음/범위 밖 번호이면 답변 보류
```

위험 점수와 등급은 기존 서버 규칙만 계산하며 챗봇은 새 점수를 만들지 않는다. 전체 대화 메모리는 넣지 않고 현재 계약 단계만 API에 명시적으로 전달한다. 이 정보만으로 답변 순서를 단계에 맞출 수 있고, 이전 대화 전체를 넣을 때 생기는 토큰 증가와 오래된 문맥 혼입을 피한다.

## 공식 자료와 색인

`legal_data/legal_sources.json`은 국가법령정보센터, 국토교통부, HUG 공식 자료의 제목·기관·URL·확인일·요약문을 저장한다. 기존 8건에 다음 4건을 추가했다.

1. 안전한 공인중개사무소 확인 방법
2. 계약금·보증금 입금 계좌 확인
3. 주택 임대차계약 신고 방법
4. 전세보증금반환보증 가입 절차

자료 파일 해시를 `case_id`로 쓰며 현재 해시의 청크가 있으면 재임베딩하지 않는다. 매물 문서용 `property_chunks`와 법률 자료용 `legal_chunks` 컬렉션은 분리한다.

## 검색과 랭킹

기본 검색은 질문 한 개를 한 번 임베딩해 Top-3를 가져온다. 실측에서 “전입신고·확정일자”와 “보증금 미반환” 질문이 핵심 법 조문을 놓쳐, 이 두 의도에만 법률 용어를 붙인 보강 질의를 추가했다. 원문과 보강 질의는 문자열 배열로 한 번에 임베딩하므로 네트워크 요청 수는 그대로다. 두 검색 순위는 보강 질의에 가중치 2를 둔 Reciprocal Rank Fusion으로 합친다.

모든 질문을 여러 방식으로 확장하거나 재랭커 LLM을 추가하지 않았다. 현재 12개 질문에서 필요한 근거가 모두 Top-3에 들어왔기 때문에 추가 비용과 지연을 정당화할 측정 근거가 없다.

## 인용 안전장치

답변에서 정규식으로 `[숫자]`를 추출한다. 번호가 없거나 제공한 범위를 벗어난 번호가 하나라도 있으면 답변을 보류하고 출처를 비운다. 정상일 때도 검색 결과 전체가 아니라 실제 인용된 출처만 반환한다. 따라서 UI에 보이는 출처는 모델이 답변에 사용했다고 표시한 근거와 일치한다.

범위 밖 질문은 LLM과 임베딩을 호출하기 전에 가벼운 도메인 키워드 검사로 거절한다. 이 검사는 후속 질문이 짧을 때 오탐할 수 있으므로 실제 대화 평가에서 문제가 관찰되면 최근 2턴 기반 분류기로 교체한다.

## 평가 방법과 결과

`python -m evaluation.chatbot --yes --reasoning none,low`는 UI 추천 질문 12개와 범위 밖 질문 5개를 실제 운영 경로로 실행한다. 검색 정답은 공식 자료 ID로 고정하고 다음을 기록한다.

| 지표 | 정의 |
| --- | --- |
| Top-K 재현율 | 질문별 필수 공식 자료가 검색 Top-3에 포함된 비율 |
| 잘못된 출처 인용률 | 답변의 번호가 반환 출처 범위를 벗어난 비율 |
| 범위 밖 거절률 | 관련 없는 5개 질문을 `insufficient`로 처리한 비율 |
| 답변률 | 관련 질문 12개에 근거 있는 답변을 반환한 비율 |
| 효율 | 입력·출력 토큰, 전체 p50·p95 지연 |

2026-09-22 실제 `gpt-5.6-luna` 결과:

| 설정 | 검색 재현율 | 잘못된 인용 | 범위 밖 거절 | 답변률 | 입력/출력 토큰 | p50/p95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| none, 검색 개선 전 | 76.9% | 0% | 100% | 100% | 10,043 / 5,440 | 3.70 / 4.81초 |
| low, 검색 개선 전 | 76.9% | 0% | 100% | 100% | 10,043 / 6,243 | 4.03 / 6.56초 |
| none, 검색 개선 후 | 100% | 0% | 100% | 100% | 10,090 / 5,357 | 3.67 / 5.07초 |

`none`은 `low`보다 p50이 약 8%, p95가 약 23% 짧고 출력 토큰도 13% 적었다. 이 과제의 답변은 검색 근거를 짧게 정리하는 작업이므로 기본값을 `none`으로 정했다. 최종 실측 결과는 `eval_results/chatbot-final/20260921-152248/`에 저장했다.

## 재현과 한계

```bash
python -m unittest discover -s tests -p 'test_*.py'
python -m evaluation.chatbot --dry-run --reasoning dry
python -m evaluation.chatbot --yes --reasoning none,low
```

새 Python 3.11 Docker 이미지에서 의존성 설치와 `pip check`, 백엔드 전체 157개 테스트를 통과했다. 평가는 고정된 17개 질문 기준이라 표현이 크게 달라진 실제 질문까지 보장하지 않는다. 공식 자료의 내용과 확인일도 정기적으로 갱신해야 한다.
